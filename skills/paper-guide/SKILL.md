# Paper Guide

## 用户入口

用户不需要运行命令。Research Starter Web UI 会把一个 PDF 放入当前 Job 的 `input/`，并在同一个 Codex thread 中承载首轮导读和后续追问。

接受的输入：当前消息附加或拖入的一个科研 PDF、用户明确给出的本地 PDF 路径，或当前任务此前明确指定的同一篇 PDF。

若消息中有多个 PDF 且目标不明确，只询问要读哪一个。若附件没有暴露为本地可读文件，直接说明该界面当前不能把附件交给本地 Docling，并请用户在 Codex 项目任务中附加或提供本地路径；不要让用户手动运行解析命令。

## 目标与边界

帮助用户更高效地亲自阅读论文。自动化 PDF 结构解析与定位，不替代完整阅读、科研判断或研究构思。

- 唯一 PDF 解析器是本地 Docling CLI。
- 不使用远程 Docling 服务、MCP、RAG、向量数据库或另一套 PDF 技术栈。
- 不搜索、下载或推荐论文；输入必须由用户提供或指定。
- Docling 失败时报告准确错误，不静默切换解析器。

## 自动执行流程

1. 从附件上下文或用户给出的路径取得 PDF 本地路径，并确认文件存在、可读、扩展名为 `.pdf`。
2. 使用 Runner 明确提供的 Job `temp/` 作为唯一解析中间目录；用户不需要选择输出文件夹。
3. 使用 Runner 明确提供的项目私有 Docling 可执行文件。找不到时简短报告环境缺失，不向用户倾倒安装命令或切换环境。
4. 对有文本层的数字原生 PDF 自动运行：

   ```text
   docling <paper.pdf> --to md --to json --output <temporary-directory> --abort-on-error --no-ocr
   ```

5. 检查退出码，并确认 Markdown 与 JSON 均存在且非空。
6. 若输出接近空白或论文明确是扫描件，说明需要启用 Docling OCR 及可能发生的模型下载；得到用户同意后才移除 `--no-ocr` 重试。
7. 使用 Markdown 阅读内容，使用 JSON 结构对象和 provenance 定位页码、章节、图、表和公式。
8. 把导读正文直接作为本轮最终回复返回，使其成为左侧聊天区的第一条助手消息。不要创建、保存或交付 `reading-guide.md`，不要只报告“已生成文件”。

## 默认模式：阅读导引

用户说“开始阅读”“帮我导读”或等价表达时，只输出：

1. 论文主要解决的问题；
2. 该问题为何值得解决；
3. 作者最核心的新方法、新发现或突破；
4. 推荐阅读顺序；
5. 优先关注的具体 Section、Figure、Equation 或 Table；
6. 阅读前可能需要补充的背景知识。

关键判断尽可能附带可核验的 PDF 页码及 Section/Figure/Equation/Table。分清作者明确陈述、上下文推断和解析不确定性。导读必须在当前回复中自包含、可直接阅读，然后停止等待左侧聊天区中的追问。不要用文件链接替代导读正文，也不要默认逐章总结、推导全部公式或解释所有图片。

## 局部问答模式

1. 在 JSON 中通过标签、caption、文本或 provenance 定位目标；Markdown 用于阅读附近上下文。
2. 只读取目标及其前后必要段落，必要时回看相关定义或前置公式。
3. 回答时先给定位，再解释问题；不因局部问题重新总结全文。
4. 若编号缺失或歧义，明确说明，并给出最接近的 page、section 和原文短语供用户核对。

推荐格式：

```text
定位：PDF page N，Section X，Figure/Equation/Table Y
解释：……
建议回看：……
不确定性（如有）：……
```

Docling JSON 的内部 `page_no` 可能与 PDF 阅读器显示页码存在基数或前置页偏差。向用户报告前必须与 PDF 实际页序核对。

## 安全与失败处理

- 不把本地论文上传到外部解析服务。
- Docling Markdown/JSON 只是当前 Job `temp/` 下的解析中间产物，不进入 `output/`、iCloud 或 Git。
- 不把解析结果自动写入 Obsidian 或其他知识库。
- 文件不可读、Docling 非零退出或输出损坏时，提供易懂摘要，不根据空内容猜测，也不更换解析技术栈。
- 密码保护、扫描件或复杂排版只在用户同意后调整 Docling 自身选项。

## 完成条件

- 用户全程无需手动运行 Conda 或 Docling。
- 默认回答是导读而非全文替代总结。
- 首轮导读正文直接出现在对话回复中，不依赖下载 Markdown 文件。
- 至少给出一个具体且可核验的论文内部定位。
- 局部追问能回到原文附近上下文。
- 全过程只依赖本地 Docling，并清楚报告失败。
