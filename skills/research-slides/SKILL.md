# Research Slides

## 用户入口

用户不需要运行命令。在 `inbox/research-slides/<任务名称>/` 建立一个子文件夹，放入说明文档与要使用的图片、图表等材料，然后在 Codex 桌面端说明演示场合、时长、页数或重点，并要求制作 PPT。

也接受当前消息直接附加的本地材料；若附件没有暴露为本地可读文件，请用户改放入上述任务文件夹，不要求用户手动执行生成脚本。

## 内容责任边界

- 用户决定科研内容、结论、重点、页面顺序和叙事逻辑。
- Agent 负责材料盘点、页面排版、信息层级、字体、留白、图片放置、题注、风格统一、PPTX 生成与视觉检查。
- 允许做衔接性补全，例如补齐简短页标题、过渡语、版式层级和明显缺失的非科研性标签。
- 不得补造科研结论、实验数值、引用、数据关系或用户没有表达的因果判断。
- 不主动联网检索资料，不自动生成科研示意图，不自动重绘数据，不用整页图片替代可编辑幻灯片，不使用 Beamer 或外部 API。
- 没有模板时默认采用极简学术风格：白色或近白背景、深色正文、单一低饱和强调色、清晰网格和充分留白。禁止装饰性渐变、复杂纹理、无意义色块、3D 效果和花哨转场。
- 若 Runner 指定了 PPTX 模板，模板优先级高于默认风格。把模板视为不可覆盖的基础文件：保留其已有页面、母版、主题、字体、配色、页眉页脚和品牌元素，只在模板副本上追加内容页；不得从空白文件仿制模板，也不得删除或覆盖模板原有内容。

## 生成前的材料关卡

1. 读取用户在当前对话中的要求以及任务文件夹内的文字型说明文件。
2. 递归列出任务文件夹中的全部文件，按“说明、图片/图表、数据、模板/参考、其他”分类。Runner 指定的独立模板路径不属于内容素材。
3. 建立逐项材料清单，为每个文件标注：计划用于哪一页、仅作参考、明确忽略、尚未决定。
4. 按用户给出的顺序形成逐页计划。没有指定顺序时，可提出最小的衔接顺序，但要明确它是补全建议。
5. 若存在重要且未被说明提及的材料，或某项选择会影响科研含义，立即暂停并提出一个具体问题。例如：

   > 文件夹里有两张结果图，但说明中没有提到。它们需要放入 PPT、仅作参考，还是忽略？如果放入，希望安排在哪一部分？

6. 只有所有重要材料都已映射或得到用户决定后，才生成 PPTX。普通装饰文件或明确标为忽略的文件无需反复询问。

## PPTX 生成

1. 把确认后的逐页计划写成临时 JSON；不要把中间计划当作用户最终成果。
2. 使用本 Skill 的 `scripts/generate_slides.mjs` 和 PptxGenJS 生成标准 16:9 内容稿。未提供模板时直接以内容稿作为最终 PPTX。
3. 提供模板时，先生成独立内容稿，再调用本 Skill 的 `scripts/append_to_template.py`，通过项目 `.venv` 中现有的 `win32com` 和本机 PowerPoint 将内容稿全部页面追加到模板副本。模板原页必须逐页保留；若 PowerPoint 或 COM 不可用，明确失败，不静默退回空白重设计。
4. 最终输出使用 Runner 指定的 Job `output/`。若用户已指定并挂载云端出口，验证完成后再投送；没有明确出口时不得猜测。
5. 保持文本为文本框、图片为图片对象、表格和图表为原生对象。不得把整页栅格化后塞入 PPTX。
6. 默认标题不小于 32 pt，正文不小于 18 pt；使用一致字体、高对比度和充足留白。标题页保持简洁。

支持的最小布局：`title`、`body`、`figure`、`two-column`、`comparison`、`conclusion`。确有内容需要时可以扩展脚本，但不要预建大量模板。

## 验证与交付

1. 检查 PPTX ZIP/OOXML 结构可读取，页数与计划一致。
2. 优先用 Codex 随附的演示渲染器直接渲染全部页面；若必须使用 LibreOffice，只能使用 Codex 依赖清单给出的随附绝对路径。
3. 查看全部页面，检查文字截断、重叠、图片变形、对比度、顺序、遗漏素材和明显占位符。
4. 发现问题时修改生成脚本或计划并重新生成，不直接手工修补成不可复现文件。
5. 报告最终 PPTX 路径；只说明已经实际验证的兼容性。本机未用 PowerPoint 打开时，不声称已在 PowerPoint 检查。

## 完成条件

- 用户给定的页面顺序与科研结论得到保留。
- 每份重要材料都有明确去向，未提及的重要素材已询问。
- 衔接性补全不引入新的科研主张。
- PPTX 可编辑且通过渲染后的逐页视觉检查。
- 输出只进入项目本地出口或用户明确挂载的云端出口。
