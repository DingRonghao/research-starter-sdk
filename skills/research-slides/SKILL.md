# Research Slides

## 用户入口

用户在 Research Starter Web UI 中选择一个必需的素材文件夹，填写内容或页面逻辑，并可另行上传一个 PPTX 模板。Runner 会把材料复制到当前 Job 的 `input/`，模板则作为独立的只读基础文件传入；用户不需要运行命令或手动执行生成脚本。

## 内容责任边界

- 用户决定科研内容、结论、重点、页面顺序和叙事逻辑。
- Agent 负责材料盘点、页面排版、信息层级、字体、留白、图片放置、题注、风格统一、PPTX 生成与视觉检查。
- 允许做衔接性补全，例如补齐简短页标题、过渡语、版式层级和明显缺失的非科研性标签。
- 不得补造科研结论、实验数值、引用、数据关系或用户没有表达的因果判断。
- 不主动联网检索资料，不自动生成科研示意图，不自动重绘数据，不用整页图片替代可编辑幻灯片，不使用 Beamer 或外部 API。
- 没有模板时默认采用极简学术风格：白色或近白背景、深色正文、单一低饱和强调色、清晰网格和充分留白。禁止装饰性渐变、复杂纹理、无意义色块、3D 效果和花哨转场。
- 若 Runner 指定了 PPTX 模板，模板优先级高于默认风格。模板是版式与视觉语言库，不是必须完整保留的成品。保留选中版式的母版、主题、字体、配色、页眉页脚、品牌元素和空间关系；模板中的示例文字、示例图表、占位内容和未采用页面默认不属于最终成果。

## 生成前的材料关卡

1. 读取用户在当前对话中的要求以及任务文件夹内的文字型说明文件。
2. 递归列出任务文件夹中的全部文件，按“说明、图片/图表、数据、模板/参考、其他”分类。Runner 指定的独立模板路径不属于内容素材。
3. 建立逐项材料清单，为每个文件标注：计划用于哪一页、仅作参考、明确忽略、尚未决定。
4. 按用户给出的顺序形成逐页计划。没有指定顺序时，可提出最小的衔接顺序，但要明确它是补全建议。
5. 当前任务没有生成前的中途确认阶段。对未被说明提及的材料，应根据文件名、邻近说明和科研叙事做保守判断，标记为用于某页、仅作参考或忽略，然后继续生成；不得因为普通材料歧义只返回问题而不产出 PPTX。
6. 若某项歧义会改变科研结论，不选择或补造该结论；可以把相关材料作为未下结论的证据展示，或保守地不采用，并在最终回复中简要指出这一限制。

## PPTX 生成

1. 把确认后的逐页计划写成临时 JSON；不要把中间计划当作用户最终成果。
2. 未提供模板时，使用本 Skill 的 `scripts/generate_slides.mjs` 和 PptxGenJS 生成标准 16:9 内容稿。
3. 提供模板时，先渲染并检查模板全部页面，识别封面、目录、章节页、正文、图表、对照、结论与结束页等可用版式。根据逐页计划选择最合适的模板页，在模板副本中复制或保留这些页面并替换占位内容；可以重复使用合适版式，但不得把未使用的模板示例页留在成品中。
4. 模板模式不得先生成另一套独立视觉风格的完整内容稿再追加。最终文件从模板副本演化而来：未使用页面删除，示例文字与示例数据替换或删除，结束页只在全部内容之后保留一次。若无法可靠编辑模板结构，明确失败，不退回机械拼接。
5. 最终输出使用 Runner 指定的 Job `output/`。若用户已指定并挂载云端出口，验证完成后再投送；没有明确出口时不得猜测。
6. 保持文本为文本框、图片为图片对象、表格和图表为原生对象。不得把整页栅格化后塞入 PPTX。
7. 默认标题不小于 32 pt，正文不小于 18 pt；模板已有字号体系优先。标题页保持简洁。

支持的最小布局：`title`、`body`、`figure`、`two-column`、`comparison`、`conclusion`。确有内容需要时可以扩展脚本，但不要预建大量模板。

## 验证与交付

1. 检查 PPTX ZIP/OOXML 结构可读取，页数与计划一致；模板模式的页数不得等于“完整模板页数 + 内容页数”。
2. 优先用 Codex 随附的演示渲染器直接渲染全部页面；若必须使用 LibreOffice，只能使用 Codex 依赖清单给出的随附绝对路径。
3. 查看全部页面，检查文字截断、重叠、图片变形、对比度、顺序、遗漏素材和明显占位符；特别检查未用模板页、示例数据、示例校名、LOGO 占位符和提前出现的结束页。
4. 发现问题时修改生成脚本或计划并重新生成，不直接手工修补成不可复现文件。
5. 报告最终 PPTX 路径；只说明已经实际验证的兼容性。本机未用 PowerPoint 打开时，不声称已在 PowerPoint 检查。

## 完成条件

- 用户给定的页面顺序与科研结论得到保留。
- 每份重要材料都有明确去向；未提及材料已经过保守判断，不因缺少中途确认而补造科研含义。
- 衔接性补全不引入新的科研主张。
- PPTX 可编辑且通过渲染后的逐页视觉检查。
- 输出只进入项目本地出口或用户明确挂载的云端出口。
