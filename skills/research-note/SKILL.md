# Research Note

## 用户入口

用户在 Research Starter Web UI 中选择一个必需的素材文件夹，并可填写补充说明。Runner 会把文件夹复制到当前 Job 的 `input/`；用户不需要运行命令、指定 Vault 路径或手工搬运成品。

首次执行和补充修改都只生成预览。Skill 在所有阶段均不得写入任何 Vault；本地保存与云端发布完全由 Runner 的机械代码完成。

## 固定环境与边界

- Runner 提供项目内本地知识镜像及本次允许的目标根目录。仅允许读取该镜像来检索已有笔记和判断目标，不得假设目标根目录具有固定名称。
- 不调用 notesmd-cli，不直接创建、追加、覆盖或删除 Markdown，不复制附件，不访问云端 Vault 进行写入。
- 不建立数据库、MCP、Obsidian 插件、同步服务或第二套知识库。
- 不自动重构目录、批量改名、移动旧笔记或统一 metadata。
- 预览中的素材仍使用 Job input 相对路径；Runner 在本地保存时会机械替换成“配置的笔记根目录/_attachments/Research-Starter/<job-id>/...”路径。

## 自动工作流

1. 读取 Runner 指定的当前 Job 素材文件夹和可选补充说明。
2. 读取投送材料；把用户明确陈述与 AI 推断分开，不将推断升级为用户结论。
3. 提取 2–5 个能代表主题的搜索词，在 Runner 提供的本地知识镜像中进行只读文件名和正文搜索。搜索仅用于参考知识组织和目录语义，不代表允许合并到旧笔记。
4. 对候选 Markdown 只读取必要内容；同名笔记位于多处时，以完整相对路径区分。
5. 决定新笔记目标。每个 Research Starter 任务默认都是独立版本，即使主题、素材文件夹或建议文件名与旧笔记相同，也不得自主合并或追加。所有目标都必须位于 Runner 在任务提示中给出的目标根目录内：
   - 可参考明确匹配的旧笔记，但仍返回一个新建目标；
   - 根据现有 Vault 目录语义选择新笔记目录；
   - 多个目标同样合理或目录含义无法判断时，选择目标根目录内最保守、最容易由用户在预览阶段识别和修正的位置，不中断后台任务提问。
6. 形成一份可以直接作为真实科研笔记使用的完整 Markdown：围绕主题、问题、方法、证据和结论自然组织，不使用“用户确认内容”“AI 简要讲解”“AI 解释”“系统整理结果”等对话过程标签。确有不确定内容时，在对应句子附近自然标注“待核实”或“推测”，不要把来源角色变成笔记结构。
7. 首次预览和每次修订都返回完整替换版本，不返回改动说明、确认话术或保存报告。素材中的图片、动图应按语义放在相关段落，使用其 Job input 相对路径，例如 `![[材料文件夹/figures/result.gif]]`；不得把所有图片统一堆到末尾。GIF 保持原格式。
8. 每次预览和修订必须严格返回以下机器可读结构，除最后的项目标题标记外不加说明：

   ```text
   <research-note-target><Runner 提供的目标根目录>/<folder/note-name>.md</research-note-target>
   <research-note-mode>create</research-note-mode>
   ```markdown
   完整正文
   ```
   <research-starter-title>不超过18个汉字的中文项目概括</research-starter-title>
   ```

9. 目标必须是 Runner 所给目标根目录下的安全相对 Markdown 路径，模式固定使用 `create`。如果建议名称已经存在，Runner 会根据所选语言生成 `-zh`、`-ja`、`-en` 及必要的数字编号；Skill 不得改用 `append` 规避重名。不得使用绝对路径、`..` 或目标根目录之外的目录。
10. 研究过程记录可参考本地镜像中已有模板语言与结构，但不强制所有笔记套同一模板。
11. 返回预览后停止。Runner 会负责保存到本地 Vault、回读验证、唤起本地 Obsidian，并仅在用户再次确认后用一次代码级 Copy-Out 发布笔记与附件。

## 写入原则

- 忠实整理用户已有内容，不替用户扩展研究结论。
- 待验证假设不得写成事实，但不要为了标记 AI 身份而破坏正常笔记叙事。
- 默认创建独立笔记版本，不改动原笔记已有段落。只有未来 UI 明确提供“更新已有笔记”且用户主动选择时，才可另行设计追加流程。
- 标题和文件名使用用户主题，避免“新建笔记”“整理结果”等无意义名称。
- 预览阶段只嵌入实际存在的 Job input 相对素材路径；不猜测最终附件路径。
- 成功后保留投送子文件夹，除非用户明确要求清理。

## 失败与停止条件

- 本地镜像或投送目录不可访问：停止并说明缺失项，不回退到云端写入。
- 搜索结果含糊：仍只返回一个保守的新建预览目标，不同时提出多个写入目标。
- 无法确定更细目录时，使用 Runner 给出的目标根目录和描述性文件名；不得返回纯提问或缺失机器结构的响应。
